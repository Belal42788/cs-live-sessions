CSS: Making Web Pages Look Great
Lesson 01
What is CSS? Understanding the Language That Styles the Web
Learn what CSS is, how it is different from HTML, the basic syntax of a CSS rule, and how a single simple rule can change the way text looks on a web page.

In the previous lesson, Building with HTML Tags and Elements, you learned how to structure a web page using tags like headings, paragraphs, and buttons. That gave your page content — words, structure, and meaning. But if you opened that page in a browser, you probably noticed something: it looked plain. Black text, a white background, default fonts — nothing styled.

This is exactly where CSS comes in. HTML builds the page. CSS makes it look the way you want. In this lesson you will learn how to:

Understand why web pages need styling beyond plain HTML
Define what CSS is and what it is used for
See how CSS works with HTML to change the appearance of elements
Learn the basic structure of a CSS rule — selectors, properties, and values
Recognize CSS styling in websites you already use every day
ℹ️
A Gentle First Step
This is your very first lesson in CSS. We will keep things simple — just the core idea of what CSS is and how it works. CSS has many properties, and we will learn them gradually in the coming lessons.

Every web page has two separate concerns: content and presentation. Content is the actual information — the words in a heading, the text in a paragraph. Presentation is how that information looks — its color, its size, how it is arranged on the screen.

Content vs Presentation
Aspect	Content	Presentation
What it answers	What does the page say?	How does the page look?
Built with	HTML	CSS
Example	A heading that says "Welcome"	That heading shown in blue, large text, centered
What a Page Looks Like Without Styling
When you write only HTML, the browser applies its own default appearance: black text, a white background, and a basic font. The content is there, but it is plain. Styling is what transforms plain content into a page that looks intentional, organized, and pleasant to read.

💡
Why Separating Content and Presentation Matters
Keeping content (HTML) and presentation (CSS) separate means you can completely change how a page looks without rewriting any of its content. This is one of the most useful ideas in web development.

CSS stands for Cascading Style Sheets. It is the language used to control how HTML elements appear on a web page. While HTML tells the browser what content exists, CSS tells the browser how that content should look.

HTML vs CSS — The Core Difference
Aspect	HTML	CSS
Full name	HyperText Markup Language	Cascading Style Sheets
Purpose	Defines the structure and content of a page	Defines the visual appearance of that content
Answers	"What is on the page?"	"How does it look?"
Example element	<h1>Welcome</h1>	Makes that heading blue and large
What CSS Can Affect
CSS can change many visual aspects of a page. At this stage, the two simplest and most common things CSS controls are:

Text color — changing how dark, light, or vivid text appears
Text size — making text larger or smaller than the browser's default
CSS has many more properties than these — colors, fonts, layouts, spacing, and much more. We will learn them gradually in the coming lessons. For now, the goal is simply to understand what CSS is and how it works.

CSS does not exist on its own — it always works together with HTML. CSS looks at the HTML elements already on the page and applies visual changes to them. CSS does not create new content; it only changes how existing content appears.

The Basic Idea
HTML creates an element — for example, a heading: <h1>Welcome</h1>.
CSS targets that same element by naming its tag — for example, h1.
CSS then describes how that element should look — for example, what color its text should be.
The browser reads both the HTML and the CSS together and displays the styled result.
📝
CSS Targets, It Does Not Create
CSS cannot add a heading or a paragraph to a page — that is HTML's job. CSS only changes how an element that already exists in the HTML will look. Think of HTML as building the room, and CSS as painting and decorating it.

Every instruction in CSS is written as a rule. A rule has a simple, consistent structure made of three parts: a selector, a property, and a value.

The Basic Syntax of a CSS Rule
CSS Rule — General Syntax
selector {
    property: value;
}
Breaking Down Each Part
Part	What It Means	Example
Selector	The HTML element being targeted	h1
Property	The aspect of the element being styled	color
Value	The setting applied to that property	blue
A Simple CSS Rule
A Single CSS Rule
h1 {
    color: blue;
}
This rule says: "find every h1 element on the page, and make its text color blue." That is the entire idea behind CSS — target an element, then describe how it should look.

💡
Always End a Value with a Semicolon
Notice the semicolon ; after blue. Every property-value pair inside a CSS rule ends with a semicolon. It separates one instruction from the next, even when there is only one instruction in the rule.

CSS is everywhere on the web. Once you know what to look for, you will start noticing it on almost every page you visit.

Common CSS Styling You See Every Day
Website Element	What CSS Is Likely Doing
Page headings	Controlling their color and how large the text appears
Buttons	Giving them a distinct color so they stand out from regular text
Body text	Setting a comfortable text size for easy reading
Every one of these visual details — colors, text sizes, how elements are presented — comes from CSS rules written by the page's developer. The HTML provided the heading, the button, and the text. CSS decided how each one would look.

ℹ️

Topic 2
How to Link CSS to HTML
Discover the three ways to apply CSS styling to your HTML pages — Inline, Internal, and External CSS — and learn why keeping structure and design in separate files makes your projects cleaner and easier to manage.

In the previous topic we learned how HTML creates the structure of a web page — headings, paragraphs, images, and links. But a plain HTML page looks very basic. To make it look good, we use CSS (Cascading Style Sheets).

CSS controls the visual appearance of a page: colors, fonts, sizes, spacing, and layout. The important question is: where do we write our CSS? There are three different places you can put it, and each has its own rules and best uses.

💡
What is CSS?
CSS stands for
Cascading Style Sheets
. It is the language used to describe how HTML elements should look on screen — their colors, fonts, sizes, borders, spacing, and more.

In this topic, you will learn how to:

Understand why CSS is usually kept in a separate file from HTML
Write Inline CSS directly on an HTML element
Write Internal CSS inside a <style> tag in the same HTML file
Create an External CSS file and link it with a <link> tag
Compare all three methods and know when to use each one
Troubleshoot common linking errors
HTML and CSS have two different jobs. HTML builds the structure — what is on the page. CSS handles the appearance — how it looks. Mixing them together in one file causes problems as your project grows.

The Problem with Mixing Structure and Design
Imagine you have a website with 50 pages and every heading needs to be blue. If the color is written inside each HTML element, you would need to change 50 files when the client decides they want green instead. But if all color settings live in one CSS file, you change one line and all 50 pages update instantly.

Scenario	CSS Inside HTML	CSS in Separate File
Change heading color	Edit every HTML file	Edit one CSS file → all pages update
Reading the code	Messy — HTML and styles mixed	Clean — each file has one job
Team work	Designers and developers edit same file	Each person edits their own file
Page load speed	Browser re-downloads styles every page	Browser caches the CSS file once
✅
The Golden Rule
HTML = What is on the page. CSS = How it looks. Keep them in separate files whenever possible. This is called the
Separation of Concerns
principle.

Inline CSS is written directly inside an HTML element using the style attribute. The CSS rules are placed as a value of that attribute, separated by semicolons.

Syntax
HTML — Inline CSS syntax
<p style="color: blue; font-size: 20px;">This text is blue and large.</p>
<h1 style="background-color: yellow; text-align: center;">Hello World</h1>
Browser Preview — index.html
index.html
Hello World
This text is blue and large.

When to Use Inline CSS
For a very quick, one-time style that only applies to a single element
When testing or debugging — you want to see a fast change
When sending an HTML email (some email clients only support inline CSS)
✅ Advantages
Immediate — no other file needed
Highest priority — overrides other CSS
Easy to test a single element quickly
❌ Disadvantages
Hard to maintain — styles scattered everywhere
Cannot reuse — you must copy styles manually
Makes HTML messy and hard to read
Very bad practice for large projects
⚠️
Avoid Overusing Inline CSS
Inline CSS is the weakest approach for real projects. It is acceptable for a single quick test, but never use it as your main way of styling a page. Use External CSS instead.

Internal CSS is written inside a <style> tag placed in the <head> section of your HTML file. All CSS rules for that page go inside this tag. No separate file is needed.

Syntax
HTML — Internal CSS using <style> tag
<!DOCTYPE html>
<html>
  <head>
    <style>
      h1 {
        color: darkblue;
        text-align: center;
      }
      p {
        font-size: 16px;
        color: #333333;
      }
    </style>
  </head>
  <body>
    <h1>My Page Title</h1>
    <p>This is a paragraph on my page.</p>
  </body>
</html>
Browser Preview — index.html
index.html
My Page Title
This is a paragraph on my page.

The h1 is dark blue and centered. The p uses the color and size from the style tag — all applied from one location inside the same HTML file.

How It Works
The browser reads the <style> tag first (inside <head>) before it renders the body. Every rule you write there applies to matching elements anywhere on that page.

For example, writing p { color: red; } inside the style tag will turn every paragraph on that page red — you don't need to add style="" to each one.

✅ Advantages
All styles for one page are in one place
No extra file needed
Good for single-page projects or quick demos
Cleaner than inline CSS
❌ Disadvantages
Styles only apply to one page — not shared across pages
HTML file becomes large if you write a lot of CSS
Not practical for multi-page websites
💡
Good For: Single-Page Projects
Internal CSS works well when you have only one HTML page and don't need to share styles. For school exercises or small demos, it is acceptable. For real websites, always use External CSS.

External CSS is the most professional and most common method. You create a completely separate file with the .css extension and then link it to your HTML file using a <link> tag inside <head>.

Step 1 — Create a CSS File
Create a new file called style.css (or any name you choose) and write your CSS rules in it.

style.css — external CSS file
/* This is the style.css file */

h1 {
  color: darkgreen;
  font-size: 32px;
  text-align: center;
}

p {
  color: #444444;
  font-size: 16px;
  line-height: 1.6;
}

body {
  background-color: #f9f9f9;
  font-family: Arial, sans-serif;
}
Step 2 — Link the CSS File to HTML
In your HTML file, add a <link> tag inside <head>. This tells the browser where to find the styles.

HTML — linking with <link> tag
<!DOCTYPE html>
<html>
  <head>
    <link rel="stylesheet" href="style.css" />
  </head>
  <body>
    <h1>My Website</h1>
    <p>Welcome to my page.</p>
  </body>
</html>
Browser Preview — index.html (styled by style.css)
index.html
My Website
Welcome to my page.

The HTML file has no style attributes. All the styling comes from style.css. If you link the same CSS file to 10 pages, they all share the same look.

Understanding the <link> Tag Attributes
Attribute	Value	What It Means
rel	stylesheet	Tells the browser that this linked file is a CSS stylesheet
href	style.css	The path (location) of the CSS file you want to load
File Structure Example
Project folder structure
my-website/
  ├── index.html       ← HTML file
  ├── about.html       ← another HTML file
  └── style.css        ← ONE CSS file used by both HTML files
Result — shared styles across all pages
Both index.html and about.html will look the same — styled by one shared style.css file.
✅ Advantages
One CSS file can style many HTML pages
HTML files stay clean — only structure, no style
Easy to maintain — change one file to update everything
Browser caches the CSS file = faster page loads
Industry standard practice for all real websites
❌ Disadvantages
Requires an extra file to manage
If the link path is wrong, the page appears unstyled

When using External CSS, the most common problem beginners face is writing the wrong file path in the href attribute. If the path is incorrect, the browser cannot find the CSS file and the page appears completely unstyled.

Mistake 1 — Wrong File Name
HTML — wrong file name (typo)
<!-- ❌ WRONG — the file is called style.css not styles.css -->
<link rel="stylesheet" href="styles.css" />

<!-- ✅ CORRECT -->
<link rel="stylesheet" href="style.css" />
Browser result — wrong vs correct
styles.css — file not found. Page renders with no styling (plain HTML).
style.css — file found. All CSS rules applied correctly.
Mistake 2 — Wrong Folder Path
HTML — file in subfolder, path not updated
/* Your folder structure: */
my-website/
  ├── index.html
  └── css/
       └── style.css   ← CSS is INSIDE the css/ folder

<!-- ❌ WRONG — does not include the folder name -->
<link rel="stylesheet" href="style.css" />

<!-- ✅ CORRECT — includes the subfolder path -->
<link rel="stylesheet" href="css/style.css" />
Developer Tools — Network tab result
Browser Console
GET http://localhost/style.css 404 (Not Found)
// The browser looked for style.css next to index.html — not inside /css/ folder

✓ Fixed with: href="css/style.css"
Mistake 3 — Missing rel="stylesheet"
HTML — missing rel attribute
<!-- ❌ WRONG — rel attribute is missing -->
<link href="style.css" />

<!-- ✅ CORRECT — always include rel="stylesheet" -->
<link rel="stylesheet" href="style.css" />
Result
Without rel="stylesheet", the browser does not know this is a CSS file. Styles are not applied.
With rel="stylesheet", the browser correctly loads and applies the CSS file.

The color Property
The color property in CSS is used to set the color of text inside an HTML element. You write it inside a CSS rule, like this:

CSS — basic syntax
selector {

3. RGB Values
RGB stands for Red, Green, Blue. You set each channel from 0 (off) to 255 (full). Mixing different amounts creates any color you want.

CSS — rgb() values

What is CSS?
CSS stands for Cascading Style Sheets. It is the language that tells the browser how HTML elements should look — their color, size, spacing, and text style. You write CSS rules that connect to your HTML elements.

Using Classes and IDs for Custom Styling
Topic 06
CSS Classes and IDs
Learn how to target specific elements on a page with precision. You will use class selectors with . and id selectors with # to write smarter, reusable CSS that keeps your code organized and consistent.

So far you have written CSS rules like h1 { color: red; } or p { font-size: 16px; }. These rules apply to every heading or paragraph on the page. But real websites need more control — some headings should be orange, others black. Some buttons should be big, others small. You need a way to target specific elements.

That is exactly what classes and IDs are for. They give you the power to apply different styles to different elements, even when they are the same HTML tag.

💡
What You Will Learn
You will understand why general CSS selectors become limiting, how to write class and ID selectors, when to use each one, and how to apply them to headings, paragraphs, buttons, links, images, and sections.

Understand why styling all similar elements together is limiting
Apply the same style to multiple elements using classes
Target a single unique element using an ID
Write CSS selectors with . for classes and # for IDs
Style headings, paragraphs, buttons, links, images, and sections independently
Reuse styles across a web page by assigning the same class to multiple elements
Choose between class and ID following clear, simple rules

The Problem
The tag selector h2 has no way to distinguish one heading from another. Every h2 on the entire page gets the same style. This is fine for very simple pages, but breaks down as soon as you need different sections to look different.

The solution is to use classes and IDs — HTML attributes that let you label elements so CSS can target them individually.

❌ Without Classes — No Control
All h2 elements look identical. You cannot change just one without affecting all others.
✅ With Classes — Full Control
Each h2 can have a different class. You style each class independently with complete precision.
A class is an HTML attribute you add to an element to give it a label. Multiple elements can share the same class name. In CSS, you target a class by writing a dot . before the class name.

An ID is also an HTML attribute, but it works differently from a class. An ID is meant to be unique — each ID should only appear once on the page. Think of it like a name tag: no two people in the same room should have the same name tag.

In CSS, you target an ID by writing a hash symbol # before the ID name.

Feature	class	id
HTML attribute	class="name"	id="name"
CSS selector	.name (dot)	#name (hash)
Can be reused?	Yes — many elements can share a class	No — each ID must appear only once per page
Best for	Groups of elements with shared styling	One specific unique element

Why Reusable Styles Save Time
If you later decide to change the card border color from gray to orange, you change just

A common question for beginners is: "When should I use a class and when should I use an ID?" The answer is simpler than it might seem.

✅ Use a Class When…
Multiple elements need the same style
You want to reuse the style later
You are styling things like cards, buttons, or paragraphs that appear more than once
You are not sure — if in doubt, use a class
🔑 Use an ID When…
The element appears only once on the entire page
It is a major structural section: a header, a footer, a sidebar
You need to link directly to it using anchor links (e.g. href="#contact")
JavaScript needs to find this exact element
Simple Decision Rule
Ask: Will this element appear more than once?
Yes → Use a class. No → You can use an ID.
Ask: Do other elements need the same style?
Yes → Use a class. No → Either works, but class is safer.
Ask: Is it a main structural section of the page?
Yes (header, footer, main, sidebar) → ID is often used here.

Key Takeaway
Classes
and
IDs
are the foundation of precise CSS targeting. Use .class for styles you want to repeat across many elements, and #id for styles that apply to exactly one unique element. The dot . and hash # are the signals in CSS that tell the browser which type of selector it is reading. Following this simple rule keeps your code clean, consistent, and easy to update.

Term	Definition
class	An HTML attribute that labels an element so CSS can target it. Multiple elements can share the same class name. Written as class="name" in HTML.
id	An HTML attribute that gives an element a unique label. Each ID must appear only once per page. Written as id="name" in HTML.
class selector	A CSS selector that targets elements with a specific class. Written with a dot before the name: .highlight
ID selector	A CSS selector that targets the element with a specific ID. Written with a hash before the name: #header
selector	The part of a CSS rule that identifies which HTML element(s) the rule applies to.
. (dot)	The symbol used in CSS to target a class. For example, .card targets all elements with class="card".
# (hash)	The symbol used in CSS to target an ID. For example, #footer targets the element with id="footer".
tag selector	A CSS selector that targets all elements of a specific HTML tag type, such as p, h1, or button.
reusable style	A CSS rule written once and applied to many elements using the same class name, reducing repetition in your code.
unique element	An element that appears only once on a web page. IDs are designed to target unique elements.
specificity	A rule in CSS that determines which style wins when multiple rules apply to the same element. ID selectors have higher specificity than class selectors. This will be explained in detail in a future advanced lesson.
