Lists: Ordered and Unordered
Master HTML lists using <ul>, <ol>, and <li> to organize content clearly — from navigation menus and feature lists to step-by-step instructions and nested categories.

Lists are one of the most commonly used structures in HTML. Every time you see a navigation menu, a product feature breakdown, a recipe, or a numbered tutorial, you are looking at an HTML list. The browser knows how to render them visually — with bullets or numbers — but what matters more is the semantic meaning they carry: related items grouped together.

HTML provides two fundamental list types. An unordered list (<ul>) groups items where order does not matter — bullet points. An ordered list (<ol>) groups items where sequence is important — numbered steps. Both types share the same child element: <li> (list item), which wraps each individual entry.

By the end of this topic, you will be able to:

Explain when to use an unordered list versus an ordered list
Write syntactically correct <ul>, <ol>, and <li> elements
Create nested lists to represent categories and subcategories
Apply lists to real-world UI patterns like navigation menus and recipe steps
Recognize and avoid common list structure mistakes
Part 1 — Why Lists Matter in Web Pages
Before lists existed in HTML, developers had to fake grouped content using line breaks and manual bullet characters. Lists solve this properly: they tell the browser — and assistive technologies like screen readers — that these items belong together as a set.

You encounter HTML lists on nearly every web page you visit:

Navigation menus — the links in a site's header are almost always a <ul>
Feature lists — product pages use bullet points to highlight capabilities
Step-by-step instructions — tutorials and recipes use numbered lists so the sequence is clear
Dropdown menus — nested lists power multi-level navigation systems
Search results and timelines — each result or entry is a list item
ℹ️
HTML Lists and Accessibility
Screen readers announce list items with their position — "list, 5 items, item 1 of 5". This gives visually impaired users context. Using <ul> and <ol> correctly makes your pages more inclusive without any extra effort.

Part 2 — Unordered Lists (<ul>)
An unordered list is used when the items have no meaningful sequence — the order could be changed without affecting the content's meaning. The browser renders each <li> child with a bullet point (•) by default.

When to use it: ingredients in a recipe, items in a shopping cart, links in a navigation bar, features of a product.

Part 3 — Ordered Lists (<ol>)
An ordered list is used when sequence matters. The browser automatically numbers each <li> starting from 1. If you add or remove items, the numbering adjusts automatically — you never update numbers by hand.

When to use it: installation steps, cooking instructions, ranking lists, algorithm steps.

Part 4 — List Items (<li>)
The <li> element is the building block of every list. It can only be a direct child of <ul> or <ol>. Each <li> can contain plain text, links, images, or even other lists (nested lists).

Nesting Rule

Part 6 — Real Website Examples
Lists are not just for academic exercises — they are the backbone of real-world UI components. Here are two common patterns every web developer uses:

Navigation bar: A <ul> containing <li> elements, each wrapping an <a> link. CSS then transforms the vertical bullet list into a horizontal menu by setting display: flex on the <ul>.
Recipe steps: An <ol> with each cooking instruction in its own <li>. Numbered automatically, easy to follow, and the order cannot be misunderstood.
✅
Key Insight
Almost every navigation menu you see on a real website is built with an HTML list. The bullets are hidden with CSS (list-style: none), but the semantic structure remains. Writing clean list HTML first is a professional habit.

Key Takeaway
Lists are simple to write but easy to misuse. The two questions to ask every time are:
Does order matter?
(yes → <ol>, no → <ul>) and
Are there sub-items?
(yes → nest a new list inside the <li>). Always wrap every item in <li> — there are no exceptions.

Week 2 — Topic 2 of 6
Links
Master the <a> anchor tag, understand the difference between absolute and relative paths, control how links open, wrap images and buttons in links, and build a real multi-page navigation system.

The hyperlink is the defining feature of the web. Without links, every web page would be an isolated island — there would be no navigation, no connections between pages, no way to reference external resources. Every time a user clicks a button, taps a menu item, or follows a search result, an HTML link is responsible.

Links are created with the anchor element <a>. Its most important attribute is href (Hypertext Reference), which holds the destination address — a path. Understanding paths is where most beginners struggle: the difference between linking to another website (absolute path) and linking to another file in your own project (relative path) is a foundational skill that affects every project you will ever build.

By the end of this topic, you will be able to:

What links do on the web and why they matter
Write correct <a href=""> elements with meaningful link text
Distinguish between absolute and relative paths and use each correctly
Control link behavior using the target attribute
Wrap non-text elements — images and buttons — inside anchor tags
Identify and fix common linking mistakes such as broken paths
Connect multiple HTML pages together to build a working navigation system
Part 1- HTML Links — Types and How They Work
The <a> tag is how you connect everything on the web. This lesson covers the three most important link types: page navigation, external links, and anchor links.

1 · Page navigation
Moving between pages of the same website
When you click a menu item and land on a different page of the same site, that's a page navigation link. It uses a relative path — just the filename, no full URL needed, because both pages live on the same server.

Code
<!-- navbar on every page -->
<nav>
  <a href="index.html">Home</a>
  <a href="about.html">About</a>
  <a href="contact.html">Contact</a>
</nav>

<!-- link inside a subfolder -->
<a href="pages/blog.html">Blog</a>

<!-- go one level up -->
<a href="../index.html">Back to Home</a>

Sending the user to a completely different website

Jumping to a section on the same page

Part 2 — Absolute vs. Relative Paths
The value inside href="" is called a path — it tells the browser where to go. There are two types: absolute (full web address) and relative (shortcut inside your project).

Absolute path — full address
Think of it like a GPS coordinate — it works from anywhere in the world.

https://www.google.com
https://youtube.com/watch?v=...
Always starts with https:// — used for external websites only.
Relative path — local shortcut
Think of it like directions from where you are — only works inside your own project.

about.html
pages/contact.html
../index.html
No https:// — used for pages inside your own site.

Part 3 — Opening Links in New Tabs
By default, clicking a link replaces the current page. The target attribute controls this behavior. Setting target="_blank" opens the destination in a new browser tab, leaving the original page intact.

When to use it: external websites (so users don't lose your page), downloadable files, documentation references.

target-blank.html
<!-- Opens in the same tab (default behavior) -->
<a href="about.html">About Us</a>

<!-- Opens in a new tab -->
<a href="https://github.com" target="_blank">Visit GitHub</a>

<!-- Security best practice: always add rel when using target="_blank" -->
<a href="https://github.com" target="_blank" rel="noopener noreferrer">
  Visit GitHub (secure)
</a>

Security Note on target="_blank"
When you open a new tab, the new page can technically access the original page through JavaScript. Adding rel="noopener noreferrer" blocks this access. Always include it when using target="_blank" with external links — it is a professional best practice.

Part 5 — Common Linking Mistakes and How to Fix Them
Most link errors fall into a small number of categories. Learning to recognize them saves significant debugging time.

Broken relative path — a typo in the filename or folder name, or a wrong ../ count. The browser shows "404 Not Found". Fix: double-check the file tree and count folder levels carefully.
Missing protocol — writing www.google.com instead of https://www.google.com. The browser treats it as a relative path and looks for a local file named www.google.com. Fix: always start external links with https://.
Missing href — the <a> tag renders with no click behavior. Fix: every anchor that should be clickable must have an href.
Forgetting the closing tag — everything after the opening <a> becomes part of the link. Fix: always close with </a> immediately after the link content.
✅
Testing Links
The fastest way to test relative links is to open your index.html directly in the browser and click through every link. If a page is missing or the path is wrong, the browser shows a 404 error immediately. Never assume a link works — always click it.

Part 6 — Building Simple Website Navigation
A multi-page website is simply a set of HTML files linked to each other with relative paths. The navigation bar — built with a <ul> as you learned in Topic 1 — connects every page to every other page.

The same navigation <ul> should appear at the top of every page in the site. Each page's own link in the nav can be styled differently (e.g., bold or a different color) to show the user which page they are currently on — this is called the "active" state and is added with CSS later.

Term	Definition
<a>	Anchor element — the HTML tag used to create hyperlinks. Requires the href attribute to be clickable.
href	Hypertext Reference — the attribute on <a> that holds the destination path or URL.
Absolute Path	A full URL including the protocol (e.g., https://example.com/page.html). Points to an exact location anywhere on the internet.
Relative Path	A path written relative to the current file's location in the project folder (e.g., pages/about.html or ../index.html). Has no https:// prefix.
target="_blank"	Attribute that opens the linked page in a new browser tab instead of replacing the current page.
rel="noopener noreferrer"	Security attribute added alongside target="_blank" to prevent the new tab from accessing the original page.
../	Directory traversal syntax meaning "go up one folder level" in a relative path.
Anchor Link	A link using #id as the href value. Scrolls the page to the element with that id — used for same-page navigation.
mailto:	A link protocol prefix that opens the user's default email client with a pre-filled recipient address.
404 Error	The browser's response when a linked file cannot be found — usually caused by a broken or incorrect path.

Part 1 — Adding Buttons to Web Pages
The <button> element creates a clickable control that the user can interact with. Unlike links — which navigate to a destination — buttons trigger actions: submitting a form, showing a menu, playing media, or running JavaScript code. Use <a> when the action navigates somewhere (a different page or URL). Use <button> when the action does something on the current page (open a modal, submit a form, toggle content). Mixing them up is one of the most common beginner mistakes.

Part 2 — Displaying Images with <img>
The <img> element embeds an image into the page. It is a void element — it has no closing tag because it has no content between tags; the image itself is the content, loaded from the src attribute.

The src attribute holds the path to the image file. This path follows exactly the same rules as the href attribute for links: it can be a relative path (a file in your project) or an absolute URL (an image on the internet).

Part 3 — Image Accessibility with alt
The alt attribute provides a text alternative for the image. It is not optional — it is a professional and legal requirement. The alt text is used in three important scenarios:

Screen readers — assistive technology reads the alt text aloud for visually impaired users
Broken image fallback — if the image fails to load (wrong path, slow connection), the browser displays the alt text instead
Search engine indexing — search engines cannot "see" images, so they read the alt text to understand what the image shows
Scenario	❌ Bad alt text	✅ Good alt text
Profile photo	alt="image"	alt="Profile photo of Ahmed"
Product image	alt="photo"	alt="Red Nike running shoes, size 42"
Decorative icon	alt="icon"	alt="" (empty — tells screen readers to skip it)
Chart or graph	alt="chart"	alt="Bar chart showing sales growth from 2022 to 2024"
💡
When to Use Empty alt=""
If an image is purely decorative — a background pattern, a divider line, a decorative icon — write alt="" (empty string). Screen readers will silently skip it. Never leave alt out entirely — that causes screen readers to read the full filename instead, which is confusing.

Part 4 — Controlling Image Size
By default, an image renders at its actual pixel dimensions. A 4000×3000 px photo would overflow the page. The width and height attributes set the display size in pixels.

Best practice: set only the width and let the browser calculate height automatically. This preserves the original aspect ratio and prevents the image from looking stretched or squished. Setting both attributes only makes sense when you want a fixed square or specific crop area.

⚠️
HTML Size vs. CSS Size
The width and height attributes set the rendered size but do not reduce the file download size. A 4MB image with width="100" still downloads at 4MB. For production websites, images should be resized and compressed before uploading. At this stage, HTML attributes are fine for learning.

Part 5 — Embedding Videos with <video>
The <video> element plays video files directly inside the browser — no plugins required. Unlike <img>, it is not a void element: it has an opening tag, optional <source> children, a fallback text, and a closing tag.

The most important attribute is controls — without it, the video has no play button and the user cannot interact with it.

video.html
<!-- Basic video with controls -->
<video src="videos/intro.mp4" controls>
  Your browser does not support the video element.
</video>

<!-- Video with multiple sources for browser compatibility -->
<video controls width="640">
  <source src="videos/intro.mp4" type="video/mp4">
  <source src="videos/intro.webm" type="video/webm">
  Your browser does not support the video element.
</video>

<!-- Video with autoplay (muted required by browser policy) -->
<video src="videos/hero-bg.mp4" autoplay muted loop></video>

<!-- Video with a poster image shown before playback -->
<video src="videos/tutorial.mp4" controls poster="images/thumbnail.jpg" width="640">
  Your browser does not support the video element.
</video>

muted	Starts the video with audio disabled
loop	Replays the video automatically when it ends
poster	Image displayed before the user presses play
width / height	Sets the video player dimensions in pixels

Part 6 — Using Media in Real Websites
Images and videos are not decorative afterthoughts — they are primary communication tools. Studies consistently show that pages with relevant visuals hold user attention longer and convert better than text-only pages.

Hero sections — a full-width image or autoplay video creates an immediate emotional impression
Product galleries — multiple images from different angles replace the need to touch a physical product
Tutorial videos — showing how something works is faster and clearer than explaining it in text
Team / about pages — photos of real people build trust with visitors
Call-to-action buttons — a strategically placed button next to a compelling image drives user action
Term	Definition
<button>	An interactive element that triggers an action. Requires a type attribute (submit, reset, or button) to define its behavior inside forms.
<img>	A void (self-closing) element that embeds an image. Requires src (the image path) and alt (the text description).
src	Source — the attribute on <img> and <video> holding the path to the media file. Accepts relative paths and absolute URLs.
alt	Alternative text — a required attribute on <img> that describes the image for screen readers, broken-image fallback, and search engines.
Void Element	An HTML element with no closing tag and no content — because the content is the external resource (image, input, etc.). Examples: <img>, <input>, <br>.
<video>	An element that embeds a video player into the page. Supports controls, autoplay, muted, loop, and poster attributes.
controls	A boolean attribute on <video> that displays the browser's built-in playback controls (play, pause, volume, seek).
poster	An attribute on <video> that specifies an image to display before the user starts playback — like a video thumbnail.
<source>	A child element of <video> that specifies an alternative media file and its MIME type, enabling cross-browser compatibility.
Boolean Attribute	An HTML attribute whose presence alone activates the feature — no value needed. Examples: controls, autoplay, muted, loop.

Building a Personal HTML Page
Apply all core HTML elements — headings, paragraphs, lists, links, images, and buttons — within a single, structurally coherent document. This activity consolidates your knowledge of HTML syntax, document structure, and element composition into one practical, real-world deliverable.

Web development is not learned by studying elements in isolation. A professional HTML document brings multiple elements together into a coherent, purposeful structure. This topic consolidates the full set of HTML elements covered in Week 2 — headings, paragraphs, unordered and ordered lists, hyperlinks, images, and buttons — into a single, working web page: a Personal HTML Page.

The personal page is a universally applicable project template. At the professional level, it mirrors the structure of a portfolio page, an about-page, or a profile section — all of which are standard deliverables in frontend engineering. Beyond the technical output, this exercise develops the habit of composing HTML documents with intention: each element earns its place, carries semantic meaning, and contributes to the document's overall information architecture.

By the end of this topic, you will be able to:

Construct a complete, valid HTML5 document from the <!DOCTYPE html> declaration through the closing </html> tag
Combine heading levels, paragraphs, and list types into a logically structured page
Embed a navigation bar using <nav> and an unordered list of anchor links
Integrate an image with a meaningful alt attribute alongside inline width sizing
Differentiate between internal navigation links and external links opened in a new tab
Add an interactive <button> element with the correct type attribute
Maintain clean, readable HTML indentation and meaningful inline comments
Part 1 — Document Shell: The Mandatory Boilerplate
Every HTML5 document must begin with a prescribed set of declarations that configure the browser's rendering environment. These are not optional — omitting any of them degrades cross-browser compatibility and accessibility.

<!DOCTYPE html> — The Document Type Declaration. It instructs the browser to render the page in standards mode rather than quirks mode. It is not an HTML tag; it is a processing instruction and must appear on the very first line of the file.
<html lang="en"> — The root element. The lang attribute declares the primary language of the document, enabling screen readers and search engines to process it correctly.
<head> — Contains metadata: information about the document that is not rendered in the viewport. Required children include <meta charset> and <title>.
<meta charset="UTF-8"> — Declares the character encoding. UTF-8 supports the full Unicode character set, including Arabic, emoji, and all Latin-script languages.
<title> — Sets the text displayed in the browser tab and used by search engines as the page title.
<body> — Contains all visible page content. Everything rendered in the browser viewport lives here.
Part 2 — Navigation: The <nav> Element and Anchor Links
Navigation is the primary means by which users move between pages or sections of a site. The <nav> element is a semantic landmark that communicates to browsers, screen readers, and search engines that its contents constitute navigational links — not body content. Inside <nav>, a <ul> containing <li> items is the canonical pattern for navigation menus.

Two distinct link types are used in navigation:

Internal links — href="index.html" — navigate within the same website. The path is relative to the current file's location.
External links — href="https://www.google.com" target="_blank" — navigate to a different domain. The target="_blank" attribute opens the destination in a new browser tab, preserving the user's current session.
ℹ️
Best Practice
When using target="_blank", add rel="noopener noreferrer" to the anchor tag. This prevents the newly opened tab from gaining access to the originating page's window object, closing a known security and performance vulnerability.

Part 3 — Content Structure: Headings and Paragraphs
Headings establish the document outline. HTML defines six levels — <h1> through <h6> — representing a strict hierarchy from most to least important. In the personal page:

<h1> — Used once, for the primary identity of the page (the author's name or the page's main topic). There should be exactly one <h1> per page.
<h2> — Used for major sections such as "My Hobbies" or "My Journey". Multiple <h2> elements are appropriate when a page has multiple coordinate sections.
Paragraphs, wrapped in <p> tags, provide prose content. The browser automatically applies top and bottom margin to <p> elements, creating visual separation without any CSS.

Part 4 — Lists: Unordered vs. Ordered
HTML provides two primary list types, each suited to different kinds of content:

Unordered List <ul> — Renders items with bullet markers. Appropriate when the order of items is irrelevant (e.g., a list of hobbies, a set of features). Each item is wrapped in an <li> tag.
Ordered List <ol> — Renders items with sequential numbers. Appropriate when sequence matters (e.g., steps in a learning journey, instructions). Each item is also wrapped in <li>.
💡
Semantic Choice
The choice between <ul> and <ol> is a semantic decision, not a visual one. CSS can make an <ol> look like a <ul> and vice versa. Use the element whose meaning matches the content — not the element whose default styling you prefer.

Part 5 — Images: The <img> Element
The <img> element embeds an image into the document. It is a void element — it has no closing tag. Its two required attributes are:

src — The path or URL of the image file. For the personal page, a relative path (e.g., profile.jpg) or an absolute URL (e.g., https://picsum.photos/200/200) are both valid.
alt — Alternative text. This is displayed when the image cannot load and is read aloud by screen readers. A meaningful alt value is required for accessibility compliance. An empty alt="" is acceptable only for purely decorative images.
The width attribute sets the rendered width in pixels. When only width is specified, the browser scales the height proportionally to preserve the image's aspect ratio.

Part 6 — Buttons: The <button> Element
The <button> element creates a clickable control. It is an inline element that accepts text content, icon markup, or even nested HTML. The type attribute is critical:

type="button" — A standalone interactive button. Does not trigger form submission. This is the correct type for buttons that are not inside a <form> element.
type="submit" — Triggers submission of the enclosing form. Must be used only inside a <form>.
type="reset" — Resets all inputs in the enclosing form to their default values.
⚠️
Omitting type is a Bug
When a <button> is placed inside a <form> without an explicit type attribute, browsers default it to type="submit". This causes the form to submit unexpectedly when the button is clicked. Always declare type explicitly.

Term / Element	Definition & Usage Context
<!DOCTYPE html>	Document type declaration. Placed on line 1 of every HTML5 file. Activates standards mode rendering in the browser. Not a tag — it is a processing instruction with no closing counterpart.
<nav>	Semantic sectioning element that wraps a set of navigation links. Communicates navigational intent to browsers, assistive technologies, and search engines. Contains a <ul> of <li><a> items by convention.
<h1> – <h6>	Heading elements defining a six-level document outline hierarchy. <h1> is the most important and should appear exactly once per page. Heading levels must not be skipped (e.g., jumping from <h1> to <h3>).
<ul> / <ol>	Unordered list (bulleted) and ordered list (numbered). The semantic distinction governs which to use: unordered for sets where sequence is irrelevant; ordered for sequences where order is meaningful.
<li>	List item. A required child of both <ul> and <ol>. It is invalid to place <li> outside a list container.
<a href>	Anchor (hyperlink) element. The href attribute specifies the link destination — a relative path for internal links or an absolute URL for external links. target="_blank" opens the link in a new tab.
<img src alt>	Void element that embeds an image. src specifies the image source; alt provides accessible alternative text. Has no closing tag. The width attribute controls rendered size in pixels.
<button type>	Interactive clickable element. The type attribute must always be declared: "button" for standalone actions, "submit" for form submission, "reset" for form reset. Defaults to "submit" inside a form if omitted.
target="_blank"	An attribute of the <a> element that instructs the browser to open the linked resource in a new tab. Should be paired with rel="noopener noreferrer" for security.
Void Element	An HTML element with no content model and no closing tag. Examples: <img>, <br>, <input>, <meta>, <link>. In HTML5, the self-closing slash (/>) is optional but not required.

Scenario
Ahmed is a DECI student building his first personal web page. He wants it to include: a navigation bar with links to his other pages and to Google, a profile image, an introduction paragraph, a list of hobbies, an ordered learning journey, and a contact button.

<head>

  <title>My Personal Page</title>
</head>
<body>

  <!-- ===== NAVIGATION ===== -->

    nav: semantic landmark for navigation links.
    ul > li > a is the standard navigation pattern.
    The third link uses target="_blank" to open Google

  <!--
    h2: secondary section heading.
    ul: unordered list — hobbies have no inherent

  <h2>My Hobbies</h2>

    <li>Programming</li>
    <li>Drawing</li>
    <li>Reading</li>

    ol: ordered list — the learning journey has a

    button type="button": standalone interactive control.

Key Takeaway
A complete HTML page is not a collection of independent elements — it is a document with an architecture. The shell (<!DOCTYPE>, <html>, <head>, <body>) provides the mandatory container. Semantic elements (<nav>, <h1>–<h6>, <ul>, <ol>) communicate structural intent. And attributes (alt, type, target) carry essential behaviour and accessibility metadata. Writing correct HTML means making intentional choices at every level.

Tables and Simple Layouts
Learn to structure data using <table>, <tr>, <td>, and <th> — build schedules, grade sheets, and pricing tables — and understand how tables were historically used for layout, and why modern CSS replaced them.

Some information is inherently two-dimensional — it has rows and columns, and the relationship between them carries meaning. A class timetable, a price comparison chart, a spreadsheet of student grades — these are all data that belongs in a table. HTML provides a dedicated set of elements for exactly this purpose.

The <table> element and its family of child elements (<tr>, <td>, <th>) give structure to tabular data in a way that both browsers and screen readers understand. Unlike using lists or paragraphs to fake alignment, tables communicate the row-and-column relationship semantically.

There is also an important historical context to understand: for most of the 1990s and early 2000s, developers used tables to control the entire visual layout of a web page — header, sidebar, content, footer — all arranged as table cells. That practice is now considered bad technique, replaced entirely by CSS Flexbox and Grid. Understanding why it was replaced helps you make better decisions going forward.

By the end of this topic, you will be able to:

Explain when a table is the correct choice for presenting information
Build a complete table using <table>, <tr>, <td>, and <th>
Use <thead>, <tbody>, and <tfoot> to organize table sections
Create real-world tables: a class schedule, a grade sheet, and a pricing table
Explain the historical use of tables for layout and why CSS replaced them
Recognize and fix common table structure mistakes
Part 1 — Why Tables Exist in HTML
Tables were created to display tabular data — information that has a natural grid structure where each cell belongs to both a row and a column, and that relationship itself carries meaning. If removing the column headers makes the data ambiguous, it belongs in a table.

Class schedules — rows are time slots, columns are days of the week
Grade sheets — rows are students, columns are assignments and scores
Pricing tables — rows are plans, columns are features and prices
Sports standings — rows are teams, columns are wins, losses, and points
Comparison charts — rows are products, columns are specifications
ℹ️
The Key Test: Is It Truly Tabular?
Ask yourself: "Does this data have rows AND columns where both dimensions carry meaning?" If yes — use a table. If you just want items to sit side-by-side visually, that is a layout problem — solve it with CSS, not a table.

Part 2 — Table Structure Basics
Every HTML table starts with the <table> element. Inside it, rows are created with <tr> (table row). Inside each row, data cells are created with <td> (table data). Every row must have the same number of <td> cells, or the table will look broken.

Part 3 — Table Headers (<th>)
The <th> element (table header) marks a cell as a column or row heading. Browsers render it bold and centered by default, but its real purpose is semantic: it tells screen readers which column or row a data cell belongs to, making the table navigable and understandable for visually impaired users.

The scope attribute is optional but recommended for accessibility — scope="col" means the header describes a column, scope="row" means it describes a row.

table-headers.html
<table>
  <thead>
    <tr>
      <th scope="col">Student Name</th>   <!-- column header -->
      <th scope="col">Math</th>
      <th scope="col">Science</th>
      <th scope="col">Average</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Ahmed</th>          <!-- row header -->
      <td>85</td>
      <td>90</td>
      <td>87.5</td>
    </tr>
  </tbody>
</table>

Part 4 — Building a Complete Table
A production-ready HTML table uses three semantic sections: <thead> (header rows), <tbody> (data rows), and optionally <tfoot> (summary rows such as totals or averages). These sections help browsers and screen readers understand the table's structure and allow CSS to style each section independently.

complete-table.html
<table>
  <caption>Student Grades — Term 1</caption>  <!-- table title for accessibility -->

  <thead>                   <!-- header section -->
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Math</th>
      <th scope="col">Science</th>
      <th scope="col">English</th>
    </tr>
  </thead>

  <tbody>                   <!-- data rows -->
    <tr>
      <th scope="row">Ahmed</th>
      <td>88</td><td>92</td><td>79</td>
    </tr>
    <tr>
      <th scope="row">Sara</th>
      <td>95</td><td>87</td><td>93</td>
    </tr>
    <tr>
      <th scope="row">Omar</th>
      <td>72</td><td>80</td><td>85</td>
    </tr>
  </tbody>

  <tfoot>                   <!-- summary row -->
    <tr>
      <td>Class Average</td>
      <td>85</td><td>86.3</td><td>85.7</td>
    </tr>
  </tfoot>

</table>

Part 5 — Simple Layout Thinking with Tables (Historical Context)
Before CSS existed in its current form, developers had no reliable tool for placing elements side-by-side on a page. They discovered that a <table> with invisible borders could position content in columns — a navigation sidebar in one cell, main content in another, a footer spanning the full width below. This became the dominant layout technique for nearly a decade.

❌ 1990s–2000s: Table-Based Layout
All blocks = <table> <tr> <td> cells with border="0"
✅ Modern: CSS Flexbox / Grid
Same visual — built with <header>, <nav>, <main>, <footer> + CSS
Both diagrams above produce visually identical layouts. The difference is the code behind them. The right approach uses semantic HTML elements and CSS for positioning — it is more maintainable, more accessible, and scales correctly on mobile screens.

⚠️
Never Use Tables for Visual Layout
Using <table> to position columns of text or images on a page is invalid in modern web development. It breaks screen readers, makes responsive design nearly impossible, and produces unmaintainable code. Tables are for data. Layout is for CSS.

Part 6 — Common Table Mistakes
Most table bugs come from a small set of structural errors. Learning to spot them saves significant debugging time.

Unequal columns: one row has 3 <td> cells, another has 4 — the table renders with visual gaps. Every row must have the same number of cells.
Missing closing tags: forgetting </tr> or </td> causes the browser to try to auto-correct, often producing wrong results.
Using <td> for headers: column titles should use <th>, not <td>. The distinction is semantic — it improves accessibility and allows targeted CSS styling.
Nesting tables: placing a <table> inside another <table> was a historical layout hack. Avoid it entirely in modern HTML.
Using tables for layout: the most important mistake — never position page sections using table cells.
Term	Definition
<table>	The outer container element for all tabular data. Every table-related element must be a descendant of this element.
<tr>	Table Row — defines a horizontal row inside a table. Must contain only <td> or <th> elements as direct children.
<td>	Table Data — a standard data cell inside a row. Renders as plain text, left-aligned by default.
<th>	Table Header — a header cell that describes a column or row. Renders bold and centered by default. Improves accessibility significantly.
<thead>	Table Head — a semantic wrapper for the header row(s) of a table. Renders identically to placing rows directly in <table>, but enables independent styling and screen reader context.
<tbody>	Table Body — a semantic wrapper for the main data rows. A table with no explicit <tbody> still creates one implicitly in the DOM.
<tfoot>	Table Footer — a semantic wrapper for summary, total, or note rows. Displayed at the bottom even if written before <tbody> in older browsers.
<caption>	A title element placed as the first child of <table>. Displays above the table and is read by screen readers before the data — equivalent to a table's heading.
scope	An attribute on <th> that declares whether the header applies to a "col" (column) or "row". Used for accessibility.
Tabular Data	Information that is naturally two-dimensional — where both the row and the column that a cell belongs to carry semantic meaning.

Forms and Inputs
Learn how to collect user data using <form>, <input>, and <label> — master input types from text and email to radio and checkbox — and build complete, accessible real-world forms like login, registration, and contact pages.

Forms are the primary mechanism through which users communicate with a web application. Every time you type your name into a search bar, create an account, fill out a survey, or complete an online checkout — you are using an HTML form. Without forms, the web would be read-only: you could consume information but never contribute or interact.

The <form> element is a container that groups related inputs together and tells the browser how and where to send the collected data. Inside the form, <input> handles the bulk of user input — and its type attribute transforms it into a text field, a password field, an email validator, a date picker, a checkbox, a radio button, a file uploader, and much more. The <label> element connects a visible text description to its corresponding input, making every form accessible.

At this stage, forms collect and structure data on the page — the part that sends it to a server requires a backend, which is covered in later levels. Here, you will master the HTML foundation that every web form is built on.

By the end of this topic, you will be able to:

Use <input> with at least eight different type values
Connect labels to inputs correctly using for and id
Use <textarea> for multi-line input and <select> for dropdown menus
Apply common input attributes: placeholder, required, name, value
Group related inputs with <fieldset> and <legend>
Build complete real-world forms: login, registration, and contact
Part 1 — The <form> Element
The <form> element is the outer wrapper for all form controls. It has two essential attributes that define what happens when the user submits the form:

action — the URL where the form data is sent. Without it, the form submits to the current page. In this level, you can use # as a placeholder since there is no server yet.
method — how the data is sent. GET appends the data to the URL (visible in the address bar — used for search forms). POST sends the data in the request body (invisible — used for passwords and sensitive data).
form-shell.html
<!-- A form that sends data to /submit via POST -->
<form action="/submit" method="POST">
  <!-- inputs go here -->
</form>

<!-- A search form that appends query to the URL -->
<form action="/search" method="GET">
  <input type="text" name="query" placeholder="Search...">
  <button type="submit">Search</button>
</form>

<!-- Placeholder during development (no server yet) -->
<form action="#" method="POST">
  <!-- form controls here -->
</form>

Part 3 — Labels: The Most Important Accessibility Rule
Every input must have a <label>. This is not optional — it is a fundamental accessibility requirement. Labels serve three purposes: they give sighted users a visible description of what to type, they give screen reader users an audio announcement of the field, and they make the clickable area of a checkbox or radio button much larger (clicking the label text toggles the input).

Labels are connected to inputs using a matching pair: the for attribute on the <label> must equal the id attribute on the <input>.

labels.html
<!-- Method 1: label and input as siblings, linked by for/id -->
<label for="username">Username</label>
<input type="text" id="username" name="username">

<!-- Method 2: input nested inside label (implicit association) -->
<label>
  Username
  <input type="text" name="username">
</label>

<!-- Method 1 is preferred — more flexible for CSS styling -->

Part 4 — Essential Input Attributes
Beyond type, four attributes appear on almost every input in production forms:

name — the key sent to the server with the input's value. Without it, the input's data is not included in the form submission. Every input that should submit data needs a name.
id — unique identifier on the page. Required for linking a <label> to its input via for="id".
placeholder — ghost text shown inside the input when it is empty. Disappears as soon as the user starts typing. Helps suggest the expected format (e.g., placeholder="e.g. ahmed@example.com").
required — a boolean attribute. The browser blocks form submission and shows a warning if this field is empty. The simplest client-side validation available — no JavaScript needed.
input-attributes.html
<!-- An email field using all four key attributes -->
<label for="email">Email Address</label>
<input
  type="email"
  id="email"
  name="email"
  placeholder="you@example.com"
  required
>

<!-- A password field — required, no placeholder (security) -->
<label for="pwd">Password</label>
<input type="password" id="pwd" name="password" required>

<!-- A pre-filled hidden value (e.g., form version tracking) -->
<input type="hidden" name="form_version" value="2">

Part 5 — <textarea> and <select>
Not all input is single-line. The <textarea> element creates a multi-line text field — ideal for messages, comments, and descriptions. Unlike <input>, it has a closing tag, and its default content goes between the tags.

The <select> element creates a dropdown menu. Each option is a child <option> element. The value attribute on each <option> is what gets submitted — the text between the tags is only what the user sees.

Part 6 — Grouping with <fieldset> and <legend>
When a form has multiple logical sections — personal info, payment details, preferences — the <fieldset> element groups related controls with a visible border, and the <legend> element provides a title for the group. Part 7 — Form Submission and the Submit Button
Every form needs a way to submit. The most common approach is a <button type="submit"> inside the form. When clicked, the browser collects all named inputs, validates any required fields, and sends the data to the action URL using the specified method. An <input type="submit"> does the same thing but is less flexible for styling.

⚠️
Any button inside a form defaults to type="submit"
If you place a <button> inside a <form> without specifying type, it defaults to type="submit" and will submit the form when clicked — even if that is not your intention. Always specify type="button" for non-submit buttons inside forms to prevent accidental submissions.

Term	Definition
<form>	Container element that groups all form controls and defines how/where data is submitted via action and method attributes.
action	Attribute on <form> — the URL that receives the submitted data. Use # as a placeholder when no server exists yet.
method	Attribute on <form> — GET appends data to the URL (for searches), POST sends data in the request body (for sensitive data like passwords).
<input>	A void element whose behavior is entirely determined by its type attribute. The most versatile element in HTML forms.
type	The attribute on <input> that defines its kind: text, email, password, number, date, checkbox, radio, file, submit, hidden.
name	The key sent with the input's value during form submission. Required on every input that should contribute data. Without it, the input is ignored by the server.
<label>	A visible description connected to a form control. The for attribute on the label must match the id on the input. Required for accessibility.
for / id pair	The mechanism connecting a <label> to its <input>. Clicking the label focuses the input. Screen readers read the label when the input is focused.
placeholder	Ghost text inside an empty input that suggests the expected format or value. Disappears as soon as the user starts typing.
required	Boolean attribute that prevents form submission if the field is empty. Browser-native validation — no JavaScript needed.
<textarea>	A multi-line text input element. Has a closing tag (unlike <input>). rows attribute sets the visible height.
<select> / <option>	A dropdown menu. <select> is the container; each <option> child provides a choice. The value attribute is what gets submitted.
<fieldset> / <legend>	<fieldset> visually and semantically groups related controls. <legend> is its title. Essential for radio button groups and multi-section forms.

  <label for="female"><input type="radio" id="female" name="gender" value="female"> Female</label>
</fieldset>

Case 4 — Button Inside Form Without type Attribute
case-4-button.html
<!-- Inside a form, a <button> with no type defaults to type="submit" -->

<form action="/register" method="POST">

  <label for="name">Name</label>
  <input type="text" id="name" name="name">

  <!-- ❌ WRONG — this button submits the form even though it's meant to show a preview -->
  <button>Preview Profile</button>

  <!-- ✅ CORRECT — explicit type="button" prevents accidental submission -->
  <button type="button">Preview Profile</button>

  <!-- ✅ CORRECT — the actual submit button -->
  <button type="submit">Create Account</button>

</form>

index.html

Name
Enter your name
👁️ Preview Profile
✅ Create Account
↑ Click Preview — no submission. Click Create Account — form submits. Same visual, different behavior.

🎯
Key Takeaway
Four rules to memorize for every form you ever build:
every input must have a <label>
connected via matching for/id;
every input that should submit data must have a name
;
radio buttons in a group must share the same name
; and
every button inside a form must have an explicit type
. These four rules alone eliminate the majority of form bugs.

Project Description
You are going to build a complete HTML Profile Page — a personal page about yourself using all the elements you learned this week, just like a simple LinkedIn page but with HTML only!

ℹ️
Why a Profile Page?
It brings all the elements together in a real, useful way. It's your first real project you can be proud of — and every web developer has one!

Your page will include:

Header — your name, photo, and a short intro sentence.
Navigation Menu — links to each section of the page.
About Me — a short paragraph about yourself.
Skills — a list of your skills or hobbies.
Education — a table showing your school history.
Contact Form — a simple form to reach you.
Footer — copyright and a link to your favourite website.
Part 1 — File Setup
Create a folder called profile-page with this structure:

project structure
profile-page/
  ├── index.html    ← your main page
  └── me.jpg        ← your photo (optional)

No personal photo? No problem!
Use a placeholder image from the internet:

Part 2 — Header
Build the first section — your name, photo, and intro sentence:

Element	Details

Part 3 — Navigation Menu
Build the navigation — links to each section of the page:

navigation structure
<nav>
  <ul>
    <li><a href="#about">عني</a></li>
    <li><a href="#skills">مهاراتي</a></li>
    <li><a href="#education">تعليمي</a></li>
    <li><a href="#contact">تواصل</a></li>
  </ul>
</nav>
💡
What does href="#about" mean?
The # links to an element on the same page that has id="about". We'll add these ids to each section below.

Part 4 — About Me & Skills
Section	Required Elements
About Me	<section id="about"> + <h2> + <p> with 2-3 sentences about you
Skills	<section id="skills"> + <h2> + <ul> with at least 4 skills or hobbies
⚠️
Remember the id on each section!
Each section must have an id that matches the href in the navigation — otherwise the links won't work.

Part 5 — Education Table
Build a table showing your school history — at least 2 rows of data:

Column	Content
Column 1	School level (ابتدائي / إعدادي / ثانوي)
Column 2	School name
Column 3	Years (e.g. 2021 - 2024)
Use <th> for headers and <td> for data cells.

Part 6 — Contact Form
Build a contact form with these elements:

Element	Type / Details
Sender name	<input type="text"> with label, placeholder, required
Email	<input type="email"> with label, placeholder, required
Message	<textarea> with label, placeholder, rows="4"
Submit button	<button type="submit">
Part 7 — Footer
footer
<footer>
  <p>© 2024 اسمك | <a href="https://..." target="_blank">موقعي المفضل</a></p>
</footer>
Deliverables
Complete index.html file.
Screenshot from the browser showing the full page.
Make sure all navigation links work correctly.
Important Notes
Every <section> must have an id that matches its navigation link.
Every <img> must have an alt attribute.
Every <label> must have a for that matches the input's id.
Use proper indentation — elements inside other elements should be indented.
Open the page in the browser and check everything looks correct before submitting.
