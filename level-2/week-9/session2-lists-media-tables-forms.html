العب مع الـ Attributes

قبل ما نبدأ: إيه اللي بيغيّر شغل الوسم؟

في الجلسة دي هنشرح عناصر زي القوائم والصور والجداول والفورم. لكن قبل ما نبدأ، لازم نفهم الـ Attributes — هي "إعدادات" بتتكتب جوه الوسم نفسه وبتغيّر سلوكه أو شكله.

1. ليها اختيارات محددة

زي type بتاع الـ <ul> — هتلاقيها Dropdown بتختار منها disc أو circle أو square.

2. نص حر

زي href بتاع الـ <a> — هتلاقيها خانة تكتب فيها أي عنوان تحب تروح له.

<a> وإزاي بتفتح اللينك

في اللينك حاجتين بتتحكموا فيه: target (يفتح في نفس الصفحة ولا تاب جديد) و href (تروح فين). جربهم:

القوائم: مرتبة، غير مرتبة، ومتداخلة

ليه القوائم مهمة؟

القوائم من أكتر الحاجات استخدامًا في أي صفحة ويب — كل مينو (Navigation Menu) بتلاقيه على أي موقع هو في الأصل <ul>. الـ <ul> بنستخدمه لما الترتيب مش مهم (مكونات أكلة، مزايا منتج، روابط مينو) والمتصفح بيحط نقطة قدام كل عنصر.

الـ <ol> بنستخدمه لما الترتيب مهم جدًا (خطوات، وصفة طبخ، ترتيب) والمتصفح بيرقّم لوحده 1, 2, 3 — لو زودت عنصر أو شلت عنصر، الترقيم بيتظبط لوحده. وأنت مش بتكتب الأرقام بإيدك أبدًا.

قاعدة أساسية: كل عنصر لازم يكون داخل <li>

جوه أي قائمة، كل عنصر لازم يكون داخل <li> (List Item). الـ <li> ممكن يحط جواه نص، أو لينك، أو صورة، أو حتى قائمة تانية كاملة.

غلط — نص من غير li

<ul> HTML CSS </ul>

النص بيتلصق في سطر واحد من غير نقط — مفيش هيكل.

صح — كل عنصر في li

<ul> <li>HTML</li> <li>CSS</li> </ul>

كل عنصر متلف في li — نضف، فيه نقط.

خطوات لازم تترتب: افتح المحرر، اعمل ملف، اكتب الكود، احفظ. الترتيب ده إلزامي — عشان كده <ol>.

لما نحط قائمة جديدة جوه الـ <li> نفسه، المتصفح بيقّعها ويغيّر شكل النقطة من • لنقطة مجوّفة ○ — قسم جوه قسم. مثال السورس: Frontend تحتها HTML/CSS/JavaScript، وBackend تحتها Node.js/Express.

أخطاء شائعة

  • كتابة نص جوه <ul> أو <ol> مباشرة من غير <li> — غلط. لازم كل عنصر يتلف في <li>.
  • استخدام <ol> لما الترتيب مش مهم — بيلبّس إنهم مرتبين.
  • نسيان وسم القفل: </li> و </ul>.

الروابط والأزرار

اللينك هو اللي بيربط كل حاجة

من غير اللينك، كل صفحة ويب هتكون "جزيرة" منعزلة. الـ <a> بيعمل اللينك، وأهم attribute فيه هو href. ولما نحط صورة أو زرار جوه الـ <a>, بيبقوا روابط تقدر تكس عليها.

الفرق بين a و button: الـ <a> للتنقل (روح لصفحة أو مكان)، والـ <button> لإجراء Action على نفس الصفحة (إرسال فورم). لو عايز زرار شكل جميل بينقّل، اتفّف الـ button جوه a.

رابط خارجي يفتح في تاب جديد

الرابط الخارجي بيبدأ دايماً بـ https:// (Absolute Path). ونضيف target="_blank" عشان يفتح في تاب جديد، و rel="noopener noreferrer" للأمان. جرب الرابطين — إحساس الـ new tab مختلف:

external-link.html · GitHub

لو حذفت https://, المتصفح بيدور على ملف محلي اسمه www.google.com ويديك 404.

المسارات النسبية والـ ../

المسار النسبي محسوب من المكان اللي الملف الحالي فيه. أنت جوه فولدر pages وعايز تروح للـ homepage؟ لازم ../index.html — الـ ../ معناها "اطلع فولدر ورا".

غلط

<a href="index.html">Home</a>

بيقّلع فولدر pages ويدور على homepage فه — 404!

صح

<a href="../index.html">Home</a>

الـ ../ صعد فولدر لورا الأول، فهتلاقي الـ homepage.

لينك يقفز لجزء في نفس الصفحة

قفزة جوه نفس الصفحة — href="#id". الـ id لازم يطابق الـ href بالظبط (حروف صغيرة و hyphens). جرب: صفحة فيها قسمين، وروابط بيقفزوا بينهم فعلًا.

anchor.html · jump links

أنواع الـ <button>

الـ <button> له أنواع: submit (بيسجّل الفورم), reset (بيرجّع القيم الافتراضية), button (معندوش فعل على الفاضي). تنبيه: أي زرار جوه فورم من غير type بيتحول لـ submit من نفسه.

buttons.html · جرب الأنواع الثلاثة

أخطاء شائعة

  • نسيان https:// في اللينك الخارجي — المتصفح بيدور على ملف محلي.
  • عدد ../ غلط في المسارات النسبية — 404.
  • نسيان href أصلاً — اللينك مش بينفع على شيء.
  • استخدام <button> للتنقل بدل <a>.

الصور والفيديو

الصورة: <img> و الـ alt

الـ <img> بياخد الصورة من src، والـ alt إجباري — بيتحكا بسكرين ريدر، وبيظهر بدل الصورة لو ما اتحملتش. لو الصورة ديكور، اكتب alt="" فارغة عشان السكرين ريدر يتجاهلها.

مقياس مهم: حدد width بس وسيب height يتحسب لوحده عشان يحافظ على نسبة الأبعاد. لو حددت الاتنين بنسب مختلفة، الصورة بتتسوّه.

الصورة المسوخة

<img src="banner.jpg"
  width="400" height="400">

بنكسر النسبة 2:1 في 1:1 — الصورة بتتسوّه.

الصورة السليمة

<img src="banner.jpg" width="400">

الطول بيتحسب لوحده — النسبة سليمة.

الفيديو: <video>

الفيديو عكس الصورة — له وسم فتح وقفل. بدون controls بيبقى صندوق أسود مش قادر تتحكم فيه. و autoplay مش بيشتغل غير مع muted. وبتقدر تحط poster صورة قبل التشغيل.

كل ده مع بعض — صفحة حية (FocusFlow)

صفحة حية فيها صورة حقيقية من الإنترنت (picsum — زي ما السورس نفسه فاعل) وزرّين وفيديو. الصورة هتتحمل فعلًا، والفيديو هيظهر رسالة لأن ملفه مش موجود.

focusflow-landing.html · combined

أخطاء شائعة

  • نسيان الـ alt على الصورة — السكرين ريدر هيقرا اسم الملف.
  • الـ alt غامض زي "image" أو "photo".
  • تحديد width و height بنسب مختلفة — تشويه.
  • نسيان controls على الفيديو — صندوق أسود.

الجداول: الأساسيات

إيه هو الجدول؟

في بيانات كثيرة بطبيعتها "ثنائية الأبعاد" — ليها صفوف وأعمدة والعلاقة بينهم ليها معنى (جدول حصص، درجات طلبة). الـ <table> هو الحاوية الكاملة، جواه بنحط صفوف <tr>، وجوه كل صف خلايا <td>.

رؤوس الأعمدة بنكتبها بـ <th> — مش <td> — لأن <th> بيعطي معنى سيمانتي للسكرين ريدر وبيبقى Bold من نفسه.

الشكل الاحترافي للجدول

الفورمات ومدخلات المستخدم

الفورم هو الوسيلة الأساسية للتواصل

الـ <form> حاوية ليها action (فين تتبعت البيانات — نستخدم # لسه مفيش server) و method (GET بيضيف البيانات في الـ URL، POST بيبعت البيانات في الجسم).

الـ <input> وسم واحد بيتغير شكله وسلوكه كليًا حسب type: text, email, password, number, date, checkbox, radio.

جرب نوع الـ Input بنفسك

غيّر الـ type وشوف إزاي شكل الـ input بيتغير فعلًا. وغيّر كمان placeholder و name — الـ placeholder بيظهر بس، والـ name هو اللي بيتبعت للـ server.

input-type.html · الشكل بيتغير مع النوع

الـ label بيربط بالـ input

اضغط على كلمة "Username" — هتلاقي الـ input بيتفعل (focus) تلقائيًا. ده اللي بيخلي الفورم سهل الاستخدام ولائق للسكرين ريدر.

أخطاء شائعة

  • نسيان ربط الـ label بالـ id بتاع الـ input — بالضغط على الكلام مش بيحصل حاجة.
  • نسيان name على الإدخال — البيانات مش هتتبعت.
  • أزرار الـ radio في نفس المجموعة بأسماء مختلفة — الاختيار بيبقى متعدد بدل واحد.
  • استخدام الـ placeholder كبديل عن الـ label — الـ label إجباري.
