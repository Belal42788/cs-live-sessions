Security Controls & Defense in Depth

إزاي نحمي نفسنا؟ وإذا طبقة حماية فشلت، إيه اللي بيمسك الموقف؟

✦

إيه هي الـ Security Controls؟

الـ Security Controls هي مجموعة وسائل بتشتغل مع بعض لتقليل فرصة الهجوم واكتشافه بسرعة لو حصل — مش أداة واحدة سحرية. قبل ما ندخل، نراجع بسرعة ثلاث حاجات مهمة:

  • Cyber Threats — أي حاجة ممكن تسبب ضرر لجهازك أو بياناتك.
  • Security Risks — احتمال إن التهديد ينجح فعلاً ويسبب ضرر.
  • Layered Protection — طبقات حماية متعددة، بحيث لو طبقة فشلت اللي بعدها تمسك الموقف.

تشبيه البيت

اضغط على كل أداة تحميات واحدة واحدة — كل ضغطة تضيف طبقة حماية للبيت:

🏠
+ الباب: أول نقطة دخول
+ القفل: مينفعش تدخل غير بإذن
+ الكاميرا: بتراقب اللي حواليك
+ الإنذار: بينبه لو حصل خطر
+ الحارس: يحمي ويواجه الخطر
طبقة حماية مضافة لسه مش مضافة

⚠️ أخطاء شائعة

  • مظنش إن حماية واحدة كفاية — حتى لو الهاكر عرف الباسورد، هيقف عند الـ MFA.
  • مظنش إن Security Controls حاجة واحدة؛ دي مجموعة وسائل مكملة لبعضها.
01

الضوابط الثلاثة: إدارية، تقنية، مادية

أي Control بنقسمه حسب نوعه لواحد من تلاتة:

  • Administrative — سياسات وتدريب: Policies, Procedures, Standards, Awareness Training.
  • Technical — برامج وأجهزة: Firewall, Antivirus, EDR, MFA, SIEM.
  • Physical — حماية المكان: Guards, CCTV, Locks, Access Badges.

أمثلة من الواقع

  • Administrative: سياسة تمنع مشاركة الباسورد، معيار "12 حرف على الأقل".
  • Technical (Antivirus): بيدور على Signature معروفة — وممكن يفوت Malware جديد أو سلوك غريب بعد التشغيل.
  • Technical (EDR): بيراقب سلوك الجهاز باستمرار (برامج شغالة، ملفات بتتغير، اتصالات خارجة، PowerShell) ويقدر يعزل الجهاز بنفسه.
  • Physical: بطاقة دخول لموظف HR بتفتحله قسمه بس، مش غرفة السيرفرات.

الفرق بين EDR و SIEM

الأداة نطاق الحماية القدرة الخاصة
EDR Endpoint واحد يقدر يعزل الجهاز
SIEM المؤسسة كلها بيجمع logs من كل الأجهزة ويعمل Correlation

مثال: نفس اليوزر دخل من القاهرة، وبعدها بدقيقتين من ألمانيا، مع تنزيل ضخم — الـ SIEM يربطهم ويقول "دي Incident واحدة".

المعركة: صُنّف كل Control

اضغط على كل أداة لوضعها في العمود الصح (Administrative / Technical / Physical):

"سياسة بتطالب كل موظف إنه يغيّر باسورده كل 90 يوم" — ده نوع إيه؟

⚠️ أخطاء شائعة

  • الخلط بين نوع الـ Control ووظيفته — النوع بيجاوب "إيه هو؟" والوظيفة بتجاوب "بيعمل إيه؟".
  • الناس بتظن إن التدريب والـ Policies مش Controls؛ بيفضلوا الأدوات التقنية بس.
02

وظائف الضوابط: تمنع، تكتشف، تصلح، تسترجع

مهم نفهم إن الـ Control Function مختلفة عن الـ Control Type:

  • Type بيجاوب "إيه هو؟" → Technical / Administrative / Physical.
  • Function بيجاوب "بيعمل إيه؟" → Preventive / Detective / Corrective / Recovery.

الوظائف الأربع

  • Preventive — يمنع من البداية، زي MFA وقفت مهاجم عرف الباسورد الغلط.
  • Detective — بيكتشف بعد ما يحصل، زي SIEM لاحظ Login غريب وبعت Alert.
  • Corrective — بيصلح بعد الحادثة، زي IT حذف Malware وسطب Patch.
  • Recovery — بيرجع الأمور لطبيعتها، زي استرجاع Backup بعد Ransomware.

  • ظن إن أي أداة تقنية وظيفتها Preventive فقط — ممكن تكون Detective زي SIEM.
03

المراقبة، الاكتشاف، ومركز العمليات الأمنية (SOC)

وجود الـ Controls لوحده مش كفاية — لازم مراقبة مستمرة (Logging, Alerting, Monitoring, Threat Detection). وفيه فريق متخصص اسمه SOC بيراقب 24/7 ويتعامل مع الحوادث. شغل الـ SOC بيمشي بخطوات ثابتة:

مثال: نظام لاحظ آلاف محاولات تسجيل دخول في دقيقة واحدة → Alert لفريق الـ SOC.

خطوات عمل الـ SOC

1 / 5

دور الـ Security Analyst

  • Monitor Alerts — يراقب التنبيهات باستمرار.
  • Investigate — يحقق في الحوادث.
  • Analyze — يحلل الأدلة والسبب.
  • Respond — يستجيب ويعالج.
  • Protect Assets — يحمي أصول المؤسسة.

⚠️ أخطاء شائعة

  • الاعتقاد إن تثبيت الأدوات كفاية من غير مراقبة مستمرة.
  • الخلط بين الـ SOC (الفريق اللي بيراقب) والـ SIEM (الأداة اللي بتجمع الـ Logs).
04

الدفاع متعدد الطبقات (Defense in Depth)

الأمان الحقيقي مش أداة واحدة، لكن طبقات بتشتغل مع بعض: People + Administrative + Technical + Physical + Monitoring = Secure Organization. لو طبقة فشلت، الطبقة اللي بعدها تمسك الموقف.

مثال: حتى لو الهاكر عرف الباسورد، هيقابله MFA، ولو دخل هيكتشفه الـ SIEM، ولو بدأ يهاجم الجهاز الـ EDR هيعزله.

⚠️ أخطاء شائعة

  • الإهمال في المراقبة؛ الطبقات مش مفيدة لو حد مش بيراقبها.
05

رحلة هجوم Phishing عبر كل طبقات الدفاع

خلينا نربط كل حاجة اتعلمناها في مثال واحد متكامل — نفس هجوم الـ Phishing بيتقابل بطبقة دفاع مختلفة في كل مرحلة:

1 / 6

⚠️ أخطاء شائعة

  • ظن إن مفيش دفاع بيوقف الـ Phishing من الأول — الـ Awareness Training بيمنع أغلب الهجمات.
  • عدم ربط المراحل ببعضها؛ كل طبقة بتتعامل مع مرحلة مختلفة من الهجوم.
A1

ابني دفاعك السيبراني

الشركة: ناشئة فيها 30 موظف، مكتب واحد، Cloud Email، Company Laptops، Customer Database، Wi-Fi Network. المطلوب: تختار على الأقل Control إداري واحد، وControl تقني واحد، وControl مادي واحد، وتشرح ليه اخترت كل واحد، وتجاوب: "أنهي Control بيقلل المخاطر أكتر؟"

Administrative: Security Awareness Training — بيمنع أغلب الهجمات من الأساس لأنها بتبدأ بإنسان.
Technical: MFA — لو الباسورد اتسرق، المهاجم لسه محتاج العامل التاني.
Physical: Access Badges — يمنع أي حد غريب من الوصول.
الجواب النهائي: مفيش إجابة واحدة صح، بس لشركات صغيرة، Security Awareness Training غالبًا بيحقق أكبر تأثير.
A2

تحدي الدفاع السيبراني

مراحل الهجوم السِتة — فكر في أفضل Control لكل مرحلة:

1. الموظف يضغط على إيميل Phishing

2. بيانات الدخول اتسرقت

3. Malware اتنزل على الجهاز

4. الهاكر وصل للسيرفر

5. بيانات العملاء اتسرقت

6. حصل Security Incident

1 → Security Awareness Training
2 → MFA
3 → Antivirus / EDR
4 → Firewall
5 → SIEM + Continuous Monitoring
6 → SOC
هل Control واحد يقدر يوقف الهجوم كله؟ لأ، كل Control بيحمي مرحلة مختلفة، عشان كده Defense in Depth.
ليه الـ MFA مهمة لو الباسورد اتسرق؟ لأن الباسورد لوحده مش كفاية.
أنهي Control بيساعد قبل ما الهجوم يبدأ؟ Security Awareness Training.
أنهي Control بيساعد بعد الاكتشاف؟ SOC / SIEM / EDR حسب المرحلة.
